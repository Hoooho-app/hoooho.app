## 本地实施与验证

前台新消息显式使用协议 2，旧任务按每条输入保留原协议。纯标点/表情/礼貌回应持久化为非事实互动，不调用整理；未知及其他人物先澄清。动态问题保存实际问句、主题、目标与单位，简短回答保留原文范围；同属性后续变化撤回旧当前断言，原对话仍可查。发生时间可绑定到单独回答，跨日使用回答时刻作相对日期锚点。身份未知的文字和图片先隔离；确认归属只能解决被回答问题的同一组材料，已经属于其他人的资料不会因后来提到当前孩子而升级。

图片经过独立的来源识别，区分逐字资料和照片可见观察；不把模糊、空白、无关图片写成正常。媒体所有权、去重与版本隔离仍在服务端验证。自然标题/摘要从逐字核验后的事实生成，并经过另一轮语义核验；程序校验数值单位与事实覆盖，编辑使旧生成结果失效。摘要后的礼貌/解释互动复用同一份已核验结果并原子更新保存资格；新事实或待澄清内容不能保留旧保存资格。过期摘要隐藏后仍由后台读取所属草稿版本，确保补充文字不重复识别图片。语义核验仍有模型误判风险，并不构成临床正确性的数学保证。

## 原始来源完整性与旧保存格式修复

`03ec05b3c7f93dc434031abf7060d3b651f93155` 已由 Production 部署 `4d351c54-b7e3-4a11-8600-335b1ab45728` SUCCESS，源分支 GitHub Actions `40222019949` 成功。真实供应商复测仍未全过：文字提取曾返回合法的主观察别名，旧 journal 只接受 symptom；另一次核验的 problems 返回过长分析而违反 schema。更关键的是“被踢到”留在原话但未进入任何提取字段，生成和核验原先都只看到字段，因而无法发现这个遗漏。可读文字照片同样在摘要核验失败。黑图、黑图加问号及原件保留继续通过。这些失败不作为成功证据。

本次修复把完整原始来源清单交给独立核验，重要来源遗漏最多触发一次补提取。补提取提示必须是已知来源/页码中的唯一逐字片段，不得来自其他人物，也不直接成为事实；第二轮仍走人物、位置、否定、时间和数值的原有校验，再重新生成及独立核验。持续遗漏直接失败，不循环、不自动保存。测试覆盖六次调用边界、显式重试预算、不同人物与昨天手部/今天足部隔离、正确拆分、取消及新输入拦截晚到递归结果。

核验问题使用有限短码，事实 ID 和来源 ID 使用当前数据生成的 schema 枚举，诊断只暴露受控短码。新的摘要封签使用 `source-entailment-v2`，哈希覆盖实际核验的完整来源清单（含未被字段引用页及来源类型），避免未引用来源改变后复用旧完整性判定；正式记录和医生摘要的引用投影继续兼容。旧 journal 在协议 2 下接受 symptom、chiefComplaint、reaction、statusRaw 的合法主观察；超出可选旧栏位长度时保留完整原字段与专业摘要，不截断原话，旧入口规则保持。

测试账号脚本可用私有临时文件复用自身生成的账号，仅登录而不重复注册；遵守现有认证限流，不记录或提交密码、会话和 token。线上测试顺序执行，清理范围仍限定自身创建的确切成员、记录和事件。
