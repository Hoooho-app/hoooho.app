# 费用总控台运行说明

`/ops/billing` 是第三方平台费用页面的集中查看器，不负责财务核算、费用预测、Runway 或多币种分析。

## 控制台入口（2026-11-01）

- `/ops`：Overview 新情况收件箱；`/ops/billing`：原费用快照面板；`/ops/feedback`：原反馈工作台。侧栏为主导航，顶栏仅管理员和退出；项目在板块内选择。备案期间使用同一 Railway Production 原生主机访问，不恢复暂停的备案域名。
- 费用来源可显式选择所属项目；既有未登记来源默认仍属于原护护记录。切换项目会筛选费用来源和汇总，更新全部只操作该项目；未接入项目为空。不复制现有数据到其他产品。
- Overview 来自现有费用快照/失败/重新登录与反馈最新用户动态；收件箱只保存独立查看回执，查看与处理状态分开。预览不确认；打开源内容、成功显示并定位之后确认。新补充/新快照使用新事件版本，旧回执不能清掉新内容；未查看跨日保留。
- 查看回执在 `DATA_DIRECTORY/ops/overview-receipts.json`；两个新接口 `/api/ops/overview` 和 `/api/ops/overview/viewed` 沿用唯一管理员鉴权。服务链接、版本管理先为空白页，未伪造监测接入或发布数据。
- 运行 `npm run test:ops` 复验；完整范围与发布回执见 `delivery/ops-console-layout-20261101.md`。

## 权限与存储

- 所有 `/api/ops/*` 请求都需要有效的 Hoooho Bearer Session，并由服务端再次校验唯一管理员邮箱。
- Railway 的服务端变量 `OPS_OWNER_EMAIL` 必须配置为唯一管理员 `wenxiaodaoray@gmail.com`；缺失或格式错误时所有 Operations 数据接口关闭。
- 元数据存放在 `DATA_DIRECTORY/ops/billing-sources.json`。
- 图片存放在 `DATA_DIRECTORY/ops/snapshots/`，该目录必须位于 Railway 私有持久化卷。
- 图片没有公开 URL。浏览器带管理员令牌请求图片后，只在当前页面创建临时 Blob URL。
- 图片响应使用 `Cache-Control: private, no-store`；JSON 和日志不包含第三方密码、Cookie、Token 或 API Key。

## 采集策略

优先级是官方 API、已授权会话下的自动截图、手动截图。当前版本建立了连接器边界与调度器，但没有伪装任何第三方平台已经接入：没有合法连接器时状态保持“尚未配置”；遇到验证码、MFA、CAPTCHA 或登录失效时必须回退为“需要重新登录”或“需要手动更新”。

每天 08:00（`Asia/Shanghai`，可由 `OPS_SCHEDULER_TIME_ZONE` 显式覆盖）串行运行已启用且不是“仅手动”的来源。调度器随应用进程启动并在每次执行后安排下一次运行；Railway 重启后会重新计算下一次执行时间。每个来源单独记录结果；单项失败不会阻止后续来源。单个平台也可以从页面点击“立即更新”。

## 历史与失败语义

- 默认页面只显示最近一次成功快照。
- 失败记录不会覆盖成功截图；页面会明确标出当前显示的是旧快照。
- 普通记录保留 30 天，标记为重要的记录不自动清理。
- 每个平台当前最新成功快照即使超过 30 天也不会被清理；完全相同的图片不会重复生成历史记录。
- 手动上传前，管理员必须确认截图已裁除邮箱、姓名、银行卡、账单地址、API Key、Token 和订单号等无关隐私。
- 服务端要求手动上传携带隐私确认；未确认的图片在写入私有存储前即被拒绝。
