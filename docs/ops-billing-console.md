# 总控台与费用自动采集

控制台入口 `/ops`，备案期间使用原 Railway Production 原生主机；不恢复暂停域名。仅唯一管理员可访问所有 `/api/ops/*`，前后端均校验身份。费用保留原快照面板，增加自动采集、费用字段和提醒；不进行付款/续费、不预测成本或混算币种。

## 页面与完整流程
- Overview：未查看的新反馈、账单快照/连接失败、到期或额度不足；打开并定位源内容成功后才记已查看，预览不清除。新补充/新快照/新风险指纹不能被旧回执清掉；未查看跨日保留，查看不等于解决。
- 费用监控 `/ops/billing`：板块内选项目，显示真实来源、采集连接、字段与私有截图；可筛选临期/不足、待核验、已读取项目正常。历史截图作为管理内可选兼容入口，日常流程不依赖上传。既有来源仍属于护护记录，其他项目未接入为空；更新全部只作用于所选项目。
- 服务链接 `/ops/services`：只检查服务端登记的应用健康端点，显示状态/HTTP/延迟/时间；未登记不判断在线。接口密钥存在只标“已配置”，不当成连通证明，不发邮件或模型请求。
- 版本管理 `/ops/versions`：显示当前实例的 Railway 提交/部署编号与私有持久启动记录。平台未提供时明确未知；仓库最新提交不代替线上版本，其他项目及原生渠道未接入不伪造。
- 工作台设置 `/ops/settings`：服务端持久保存日期和额度阈值，保存失败保留输入；仅站内提醒，无自动邮件/短信。

## 采集与事实语义
后台每天08:00 Asia/Shanghai串行运行，到期任务在重启后补采；周任务按北京时间7个自然日间隔，来源并发请求合并，单项超时或失败不阻塞其他来源。未授权来源不反复写定时失败历史。重新登录期间暂停定时采集，完成原平台验证后核对保存连接。失败保留旧图/旧事实并标明待核验，相同图片不复制文件，但独立更新已读取字段的核验时间。截图成功不证明费用正常。

默认提醒为30/7/3天、额度剩余20%/5%，可在工作台设置更改。到期按北京时间自然日判断；额度重置日期不当付款日。余额必须有明确币种，正余额没有提醒值时不单独判正常；日期须有含义，无法确认字段保持未知。日采集超过36小时、周采集超过8天不显示正常；历史风险仍显示“上次读取，尚待复核”。自动续费开关是独立事实，未知时不猜测。

## 分类与不同计费结构
用途与计费方式分开保存。默认用途：服务器与存储（阿里云、Railway、Volume、Cloudflare）、运营管理（Resend、GitHub、Figma）、AI 与 Agent（OpenAI、ChatGPT/Codex）、域名与发布（Apple Developer、域名）。管理员可在管理内修改；同一来源可同时按量+订阅+存储。分类筛选与计费方式筛选叠加，统计只计当前项目和筛选范围。

字段由平台类型与已核对连接决定：域名只有注册到期；Volume为存储用量、单价、费用、周期；订阅为套餐、订阅金额、下次扣款等。连接后仅显示确认过的字段及实际新增事实，缺失不补0。账户级费用明确未按项目分摊，币种不合计。平台预计成本来自原账单，系统不推算。

明确预付费余额0才报耗尽，按量后付费不据此报欠费；平台明确欠款独立提醒。附赠额度用完提示核对超额计费，明确硬限额才报用尽。结算期结束不是服务到期；下次扣款只提示付款方式。存储有同单位实际容量时才判断使用率。

## 一次登录、核对后自动采集
官方RDAP继续自动读取域名注册到期，无需账号授权。其他已登记来源的“连接采集”流程：
1. 管理员明示同意将选定平台的独立登录状态留在私有采集服务。
2. 在控制台内的私有平台窗口本人登录/验证码，进入账单页；可导航、滚动和选择账单区域；点击画面中的输入框后，直接在原位输入或粘贴，支持中文输入、Tab/Shift+Tab切换和Enter确认。当前焦点有绿色边框与文字反馈，普通输入框无需下方二次发送。不能发送密码/验证码到聊天。
3. 确认币种，读取当前账单。识别仅使用DOM明确标签与唯一值，不用外部模型/OCR，不猜模糊日期或金额。
4. 核对提取值和已遮罩的区域预览，选择要持续读取的字段，明确确认后保存。
5. 后台立即重新读取，成功后回到费用卡显示真实数值和核验时间；之后按日/周自动采集。登录过期或标签变动显示待重连，保留旧图与字段。

保存前再次比对页面版本，变化时要求重读。操作绑定会话/页面版本；关闭/15分钟无操作终止授权窗口，晚到操作不跨平台输入。一个浏览器串行使用，交互期间后台不抢占。授权窗口图流不落盘；只有明确核对的账单区域保存为私有快照。查看快照不等于授权，不代付/续费/改套餐，不绕过验证。

## 私有采集部署
既有Production中的独立服务 `ops-billing-browser`，无公开域名和CDP端口。Docker仅含采集代码、DOM解析器和共享字段目录，不含健康业务代码、数据、产品API密钥或认证密钥。独立 `/profiles` 持久卷；1GB内存/1vCPU限制，空闲浏览器关闭。开机先实际启动Chromium并截图诊断，成功才通过健康检查。

健康应用只配置 `OPS_CAPTURE_WORKER_URL`（私网HTTP地址）和 `OPS_CAPTURE_WORKER_TOKEN`（服务器间秘密/引用）。采集服务单独配置 `OPS_CAPTURE_WORKER_TOKEN`、`OPS_CAPTURE_STORAGE_KEY`（64hex，AES256-GCM加密其自身会话cookie）、`CAPTURE_DATA_DIRECTORY=/profiles`、`PORT=8080`。密钥不得前端化或提交；产品服务不持有存储加密密钥。浏览器使用新建平台会话，不导入用户本机cookie。加密cookie恢复最长30天，平台可提前撤销，持久profile保存本平台登录的localStorage；只允许登记供应商和身份域名，拒绝HTTP/私网文档。`/health`只返回非敏感健康，其他私网接口全部需要服务器秘密，主应用中转仍验证唯一管理员。

旧 `OPS_BROWSER_CDP_URL` / `OPS_CAPTURE_PROFILES` 只保留兼容现有手工配置，新连接直接在控制台完成，不让用户修改服务器JSON。

## 权限、存储和验收
- `OPS_OWNER_EMAIL` 唯一管理员缺失/格式错误时接口关闭。服务端秘密不出现在JSON、浏览器或日志。
- 原 `/data/ops/billing-sources.json` 和私有 `snapshots/` 保留；图片仅管理员Bearer读取，响应private,no-store，无公开图片链接。
- `overview-receipts.json` 保存独立查看回执；`workspace-settings.json` 保存阈值；`web-releases.json` 保存本实例真实提交记录。
- 普通图片历史保留30天；最新成功图与重要图不自动清理。兼容手动导入仍必须明确确认隐私裁除，不能伪装API来源。
- `npm run test:ops` 覆盖持久化、权限、事实/风险、真实Chromium合成账单截图、页面与完整源定位；外部供应商接通状态必须另行核验，不能用合成测试冒充。
- 本次发布与待本人授权项见 `delivery/ops-billing-live-fields-20261101.md`。

## 输入与画面一致性
当前焦点可在嵌套/跨域登录iframe内；仅返回控件类型、标签、矩形和是否已有值，绝不返回其内容。已有值未编辑时保留；本地输入为替换该字段，明示占位提示。输入仅当前焦点短时保留，密码遮罩，无持久化或日志。输入合并串行同步；切换前先同步，失败保留可重试并中止后续按键。待切换的旧控件暂时只读，新焦点可继续输入，快速Tab不丢失。画面与状态同请求返回，迟到轮询不能覆盖新焦点；点击绑定实际已显示画面的页面版本，不能用新页面版本执行旧画面坐标。关闭清理未发送输入。普通截图和旧API保留兼容。
