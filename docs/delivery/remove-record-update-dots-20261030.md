# 移除全局新增记录红点（2026-10-30）

## 用户任务与验收契约

- 用户决定：记录了一件事后，不再用全局红点提示某处新增内容；整套记录未读提示功能删除。
- 基线：健康仓库 `Hoooho-app/hoooho.app`，干净 `origin/main` `0d19a43eab782faef3ba17c288c2f8770b58c00c`；隔离分支 `codex/remove-record-update-dots-20261030`。提交前跟进最新主分支 `7927c85809e598aeea8374b01f82ccc5bfa0d09a`，完整保留同期已确认的静态护士与小屏改动，并重新核验合并后的版本。
- 普通案例：家长给当前孩子保存一条情况或档案，仍按真实保存回执获得结果；打开日历、详情、档案并返回、刷新或切换孩子，记录继续可读，各入口均无新增/未读红点。
- 删除范围：菜单、底部导航、月历日期、档案分类、症状跟进入口的记录更新红点；保存时的标记生成、上传回执补标记、页面打开时已读处理、日期聚合、专用状态与样式。
- 升级：启动时只移除 `hoooho-record-updates-v1` 旧提示缓存，不读取或解析其中内容；缓存损坏、清理被浏览器拒绝也不阻断启动。不清理账号、原始输入、草稿或正式记录。
- 保存、失败重试、数据变更刷新事件、对象归属、日期顺序、详情/编辑/导出等既有业务照常。移除提示不改变成功定义，不新增确认步骤或新提示形式。
- 冻结：页面布局与导航结构、文案、图标方案、护士素材、后端接口和数据、AI、其他功能。记录分类/真实记录数量、录音和错误等业务状态不属于本次记录未读提示。

## 分支与核验

| 分支 | 验收 |
| --- | --- |
| 保存新记录或档案 | 真实记录持久化可回读，旧提示缓存不再生成，所有上述入口无红点 |
| 已有旧标记、其他孩子或账号的标记 | 升级不显示，切换对象后也不出现；仅清理旧提示键 |
| 返回、刷新、关闭和重开详情 | 同一记录仍可读，不再执行提示已读写入 |
| 保存失败与重试 | 维持现有错误和重试，不以红点代替真实保存回执，不重复创建 |
| 旧缓存损坏或清理失败 | 页面仍正常打开，内容不丢，红点仍不渲染 |

## 实现与本地证据

- 删除专用 `src/features/record-updates/`（组件、状态、日期聚合、样式及原有功能测试）；移除全部 13 个消费/生成位置，包括 API 成功后的追加标记和档案上传的额外标记。
- 保留 `apiClient` 的 `hoooho-data-changed` 事件及原有保存回执、会话恢复、资料归属、失败重试和页面数据读取。`src/main.tsx` 仅清理一个旧提示键，清理异常不会阻止启动。
- 更新原有浏览器验收中的红点预期，覆盖有记录的日期、混合记录、档案入口和旧缓存；混合记录的测试初始化使用隔离真实记录，不依赖历史 AI 核对按钮。真实手动保存与失败重试由新版手机用例验证。
- 增加 `tests/record-update-removal/`，并接入已有 Smart record CI；没有新增常驻服务、真实供应商调用或原生发布步骤。
