# 首页新建对话等待排查

基线：`main@838995b596aa80f05e65da307f950aefb721d1a5`，干净工作区；任务分支 `fix/home-new-conversation-latency`。

## 任务契约

家长在当前孩子首页已有一段对话时，点击新建，旧对话及未发送文字/录音留在侧栏，新首页可继续输入；正式健康记录不变。仅修复本入口及其初始化依赖，不改变 AI、导航、后端协议和页面版式。

- 已从本机恢复且按钮可用时，新建不应等待后台的最新对话 GET。初始化中可能产生写入的旧资料迁移、取消命令仍须有序完成，避免关闭后又创建旧会话。
- 本机旧草稿归档成功、服务端关闭会话有回执之后才显示新建成功；失败保留原内容并允许重试。新建不是删除历史/健康记录。
- 点击立即反馈进行中，重复点击只关闭一次；旧恢复结果不能覆盖点击后的意图。切换账户、孩子或离开后不能更新新页面。
- 新建完成、刷新、侧栏重新打开旧对话：新首页不恢复旧消息；历史保留文字、未发送补充和原件。新建不调用模型、不自动保存健康事实。

## 源码发现与验证计划

`SmartRecordWorkspace.newConversation` 先等待整个 `initialization.current`；但首页已在本机恢复后设置 ready，初始化还会做 latest GET。该 GET 无论是否仍与用户意图相关，都阻塞新建。之后还串行等待本机归档、服务端 closeSession 和新草稿持久化。`closeSession` 仅关闭会话并保留历史/正式记录，不等待模型结果。

计划用本地真实浏览器、真实草稿持久化及合成账号复现：扣住 latest GET，点击新建，验证不等它返回；再释放旧响应，验证不会覆盖空白页。补查关闭失败/重复点击、刷新和历史未发送内容恢复。此受控延迟证明阻塞机制，不代表用户现场网络耗时。

## 实施与结果

- 分开初始化的写入依赖与后台读取：新建等待资料迁移/取消和本机写入，随后关闭会话，不再等待 latest GET；立即使旧读取结果失效并显示按钮加载态。保留服务端关闭回执与草稿归档顺序，新增离页/身份核对。
- 反例：基线挂起 latest GET 后，点击新建 1.5 秒内仍无空白页；修复后同一请求仍挂起时，1.5 秒内出现可输入空白页，关闭恰好一次。释放旧响应及刷新后不恢复旧消息；侧栏重开保留未发送补充。
- 真实 Chromium，390×844、合成账号与本机/测试服务持久化：新增3项通过（慢读及迟到结果、双击及关闭失败重试、旧资料迁移先于关闭）；已有35项导航/侧栏/档案回归通过。首次新测试有2项因“记录介绍”同时匹配内外两个区域而失败，改用精确可访问名称后3项全部通过，未放宽时限或业务断言。
- 草稿单测8项、会话关闭/恢复/删除服务测试30项通过。完整 `npm run build` 通过，最终图标加载态调整另经 Vite 构建；不新增依赖，不调用真实供应商，不写生产健康数据。
- 已查看新建完成后的手机尺寸截图；这是桌面 Chromium 手机视口，不是实体 iPhone 验证。受控延迟只证明并修复串行等待机制，尚无用户现场请求轨迹可量化其当次慢速。
