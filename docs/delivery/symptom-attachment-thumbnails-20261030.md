# 手动症状附件：紧凑展示与原件保存

基线：`08b11b6`；产品主人确认于 2026-10-30。本次只调整「记录症状」手动页的附件区及其上传入口，保留首页、既有资料整理页、原生三来源菜单与保存归属。

普通案例：家长手填症状，在「补充信息」与「发生时间」之间点附件行右侧的加号，选择一张照片。该行左侧为图片图标及「附件」，加号始终在右侧；下方只显示照片缩略图，不显示数量、文件名、大小、日期、识别状态或识别结果。可继续点同一加号添加照片／视频，点缩略图查看，点删除移除。右上角保存后附件关联同一条症状记录，重开仍保留原件。

规则与验收：

- 空态是一行，保留至少 44px 点击区域；有附件后仅增加缩略图高度。320／375／390／430px 宽度均不横向溢出，加号始终与标题同行且靠右。
- 本页新上传照片／视频只保存原件及生成兼容预览，不启动内容解析；客户端不轮询解析、不提供应用到正文入口。服务端使用显式跳过解析的上传选项，旧调用默认行为不变。历史已存在的解析数据不删除，也不在本页展示。
- 取消选择不改变正文／附件；连续添加最多六份，达到上限加号仍在原位但禁用。照片／视频格式与体积限制沿用现有规则。
- 上传中仅缩略图 loading；失败时保留原件并提供重试／移除。刷新、返回重开、保存失败重试沿用账户／孩子／草稿归属，已上传附件不重复上传，解析不覆盖手填正文。
- 手动症状表单的其他字段、右上角保存及已有草稿保护不变；其他入口继续提供原有资料解析与核对能力。

实现责任：`SymptomRecordFlow` 管理本页布局与模式；`QuickRecordPhotos` 管理缩略图、原件、上传恢复及解析轮询开关；`quickRecordService.uploadMedia` 传递跳过解析选项；服务端 quick-record media 路由决定是否启动解析。验证以本地浏览器真实上传／回读、相关客户端检查、既有资料整理回归、构建及 Production 发布为依据，不调用真实 AI、不写入正式健康数据。上线与实体 iPhone 验收分别记录，不混称。
