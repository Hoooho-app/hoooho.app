# OpenRouter 接入任务契约

日期：2026-10-29（Asia/Shanghai）。基线：`fc7d65bc38a376de51dd570cec386fb004e55221`，干净 `origin/main`；任务分支 `codex/openrouter-provider-20261029`。

## 目标与边界

负责人希望实际比较千问与海外模型的回复、追问和整理效果，已授权直接准备 OpenRouter 接入。付款卡为大陆发行 Visa。注册、余额、API Key 和模型地区资格尚未验证；不能将支付渠道可用视为模型可用。

新增显式 `AI_PROVIDER=openrouter`，服务端使用独立 `OPENROUTER_API_KEY`、明确指定的模型 ID，接通前台对话、护士文字对话、结构提取、图片/PDF 逐页识别和下游摘要展示/导出。沿用原提示词、JSON Schema、事实校验、账号/成员归属、版本与保存回执，不调整页面设计或业务流程。ASR、TTS 和实时音频继续使用各自原配置，不声称这些能力已更换。

默认仍按原配置运行千问；未配置或调用失败时明确失败，不暗中改用其他付费模型，不自动重试。回退指运维恢复原来的 `AI_PROVIDER=bailian`，不是测试失败后静默调用千问。

## 普通完整案例

1. 家长在当前孩子的前台输入“昨天咳嗽，今天没有发热”。原话按当前事项保存为来源。
2. 仅当服务端已显式选择 OpenRouter、存在 Key 和固定模型 ID 时，前台将同一提示词、历史及来源经 OpenRouter 发出；结构提取使用同一供应商配置。诊断保留供应商、模型、请求标识和 token 计数，不记录原话或 Key。
3. 模型输出须完整、非拒绝、合法 JSON 且通过原 Schema/业务校验后，才可展示为有效回复/候选。用户改口“是今天开始咳”沿用原版本与来源更正规则。
4. 用户确认生成/保存时仍由原业务服务校验版本和归属；以真实保存回执进入详情、列表及导出。更换模型不增加自动保存或重复记录。
5. 上传报告照片或 PDF 时，图片仅用本次内联数据，PDF 本地逐页转图；不发送公开附件链接，不把文字模型当成语音服务。

## 验收与真实程度

- 适配器测试必须使用注入的合成 transport，验证 endpoint、结构化参数、受控次数、取消、错误和输出校验；不将其当作模型理解能力证据。
- 核验前台/护士/整理入口均可显式选到 OpenRouter；旧配置继续运行千问。ASR/TTS 独立。
- 必要构建、相关服务与展示/导出回归、移动页面兼容检查；本次不更改 UI。
- 提交、推送、合入 main、Production 部署与只读健康/版本核验按项目既有授权完成。无 Key 时保持线上原供应商，不激活未验证模型。
- 当前没有 OpenRouter 凭据或充值授权：不执行真实付费调用或写入生产健康数据。接入代码发布与真实模型验收分开报告；待 Key、余额、资格和模型选择齐备后再做实际对照。
