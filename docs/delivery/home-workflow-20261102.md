## 完整任务与业务规则

普通案例：家长进入空白首页，看到“孩子下午开始发热、没精神”的症状框。箭头向下衔接说话气泡，护护问体温，演示填写38.2℃，整理成待核对记录单，模拟确认后才显示保存，再示意傍晚补充37.5℃。家长随后直接使用原输入栏说自己的情况；第一条真实气泡出现后介绍整体卸载，真实确认、保存、重开/编辑沿用现有记录链路。

演示使用固定虚构情景，明显标记“演示”，不读取孩子健康事实、不发送消息、不调用AI、不生成草稿、不写记录、不领取奖励。演示内“已保存”和五段线仅属于虚构情景，不充当真实保存回执。

| 状态/分支 | 规则与负责位置 |
| --- | --- |
| 逐幕推进 | FrontDeskWorkflow 独立本地时钟，约22秒单次播放；症状框、语音原话、追问、待核对/保存、变化记录逐一出现 |
| 暂停/恢复/重播 | 保留当前幕及已播放时长；播完静止并可重播，重播恢复第一幕，不产生业务副作用 |
| 输入/录音/后台/弹层/离屏 | 暂停JS推进与CSS动效；恢复仍从当前幕继续；卸载清理计时、观察器及事件 |
| 减少动态效果 | 静态当前幕，不自动推进；通过“下一步”逐幕查看五幕，再可重播，不摊开整条流程 |
| 真正开始记录 | 首条气泡后随欢迎区卸载；未发送、取消录音/附件不卸载；原输入、草稿、原件与对象归属保留 |
| 新建/刷新/切换对象 | 新空白首页恢复演示，不沿用上一对象的健康数据；演示不需持久化，正式对话仍按现有协议恢复 |
| 小芽导航/领取失败 | 原呵护之旅处理真实状态、重试和账户/日期幂等；首页不再有第二个领取按钮 |
| 窄/短屏 | 按真实宽度排版，保持可读字号；窄屏压紧示例文字，短屏允许自然滚动，原输入始终可达 |

V2 token、HohoButton、HohoProgress 五段线与现有Material图标复用；截图中的UI字段只在示意卡内部，不改真实表单。
