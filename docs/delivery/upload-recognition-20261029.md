# 上传后部分识别结果的展示与核对

日期：2026-10-29（Asia/Shanghai）。基线：`40e690705c5eaf0d12631d8618e3d9039528a2f0`，干净 `origin/main`；隔离分支 `codex/preserve-upload-recognition-20261029`。

## 任务和边界

用户确认按“上传成功，已有识别内容被整体隐藏”的反例修复，并检查其他上传入口的同类问题。家长上传照片、PDF 或视频后，应看到已有的识别草稿、尚缺的内容及下一步；核对后保存，重开仍是同一条记录和原件。

本次修改结果投影、待核对展示和明确采用，不更换模型、扩大供应商调用预算、增加声音识别能力或重构视频独立记录流程。保留生成记录单及正式保存的显式授权、原话先保存、人物归属、时间和版本保护。旧网页缓存是上轮独立发现，不能冒称为这条反例的已确认根因。

## 普通完整案例

家长选择当前孩子，上传两张照片。已识别一段可核对文字，但一页不清楚或发生时间尚未确认。对话先显示已有识别草稿并说明待核对原因；不因一个警告把所有内容隐藏。用户同意生成记录单，在编辑区对照原件核对识别内容，明确完成修改，再保存。记录详情与导出使用这个已确认正文，原照片仍能打开。重试或刷新不新增正式记录。

## 状态与不变量

- 原件上传、识别草稿可读、已核对正文、结构化结果可写、正式保存分别成立。展示待核对内容不解除原有结构化保存与档案更新校验。
- 前台只投影同一成员、同一事项和当前证据版本的识别结果。旧版本、已撤回内容或另一对象的结果不进入当前草稿。
- 有来源的部分结果可以展示；未确认主体只能查看，不能一键归到当前孩子。不确定时间不能以上传时间冒充。
- 当前记录单的正文仍以用户编辑和现有可保存结构化结果为准。待核对材料单独展示，只有明确采用及完成修改后才进入正文。未采用时可以明确只保存原话和原件，不把它表述为识别完成。
- 同一个来源批次有多个候选时，采用其中一个只标记该候选；其他候选和不完整提示继续可见。
- 图片字段面板的“部分”状态也检查草稿自身的待核对项、页面警告及来源不确定性，不能只依赖最外层任务状态。

## 分支与恢复

| 分支 | 行为与恢复 |
| --- | --- |
| 多图/PDF一页失败、一个条目待核对 | 显示已有识别内容和具体待核对状态；允许按原件编辑，不整批清空 |
| 视频口述或画面一项失败 | 另一项成功的文本继续显示，失败项独立重试；不声称听出了非语言声音 |
| 人物不明/明确他人 | 显示归属问题，保留结果，不能直接采用到当前人物 |
| 用户编辑、连续补充和迟到结果 | 当前证据版本与编辑优先；新旧内容不得混入同一采用操作 |
| 取消、返回和刷新 | 原件、当前已采用正文与仍待核对条目恢复；取消编辑不保存候选 |
| 保存失败/丢失回执/重复点击 | 沿用原保存幂等键和精确记录 ID，重试不得重复创建 |
| 仅保存原话和附件 | 保留既有能力，明确与识别内容采用区分；不把未核对结构化字段写入档案 |

## 验收与审查范围

- 前台投影：待核对项、来源不确定、一页警告分别保留可见识别结果；对象和证据版本保护仍成立。
- 浏览器：上传后在对话看到部分结果；生成、核对、取消、采用、保存、重开与原件查看；多个候选采用一个后其余仍可见。
- 其他入口：用药、用药提醒、就诊、接种共用图片字段面板；健康随记及症状记录的图片/视频独立阶段；附件摘要与智能记录审核。
- 程序使用合成供应商和虚构资料，验证实际本地持久化与页面，不据此宣称真实模型或实体 iPhone 已验收。Production 验证遵守既有预算和数据边界，不新建 Staging、不自动上传 TestFlight。
