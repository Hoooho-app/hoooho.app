## 用户任务与普通案例

家长在已有症状对话里上传一张收费/检查项目单。原件上传后，当前图片必须进入可核对的识别任务；首轮读图所得的单据内容先显示，再由家长决定是否生成记录单、核对归属与正文、显式保存。取消不产生正式记录。保存后聊天、日历与原件仍是同一份结果。

收费/申请单上的项目不代表已经完成检查或取得结果；不补造数值、诊断、发生时间。资料可能属于其他人，临时阅读不等于归档到当前孩子。看不清内容保持未知。首轮完成与正式整理、保存分开，不以占位文案冒充已识别。

## 已观察到的故障与证据边界

用户截图显示 04:00 上传图片，04:06 仍在转圈。2026-10-29 04:00 附近（Asia/Shanghai）的 Production 只读日志显示原件 POST 201（约332ms），随后识别任务 POST 409（约5ms），GET 返回的是原有生成任务；相邻旧对话访问404。仅凭HTTP日志尚不能确定409的具体业务码。

源码确认 enqueue 的异常处理将“旧任务存在”无条件当作新输入已接收，未核对该不可变消息ID是否出现在任务 inputStates；本地新图片因此可长期保留 pending。恢复轮询也不会将任务未接收的本地 pending 输入转为可重试失败；旧上下文404又可能阻止进度回执持久化。这不是已有证据支持的六分钟模型执行耗时。

## 状态与恢复规则

| 分支 | 下一步、保留内容及副作用边界 |
| --- | --- |
| 原件成功、任务拒绝 | 只把包含当前不可变输入ID的回执视为接收成功；否则明确显示未开始识别及重试，保留原件、输入ID和上传资源ID，不空转 |
| 回执丢失 | 回读相同任务，核对当前输入的确已接受才恢复进度；不因查到旧任务就宣称成功，也不盲建重复任务 |
| 已取消/失效的任务或上下文 | 不复活取消内容。新的明确输入或显式重试可用新的接收任务，仅携带本条输入与原件；清除已失效的问题/草稿绑定，不重送旧对话。普通失败仍复用原任务和已完成检查点 |
| 刷新后残留未接收输入 | 在权威任务回执和本地提交队列空闲后显示可重试失败；正在上传/排队的输入不被误判；不自动发起付费识别 |
| 首轮图文已读出、完整整理仍未执行 | 立即展示有当前来源的可读内容及是否整理入口；生成前暂缓完整整理，复用已有读图，不追加首轮调用；不能把未核对内容当作正式保存 |
| 多图、错误、切换对象或新输入 | 每条输入按自己的ID/来源接收；迟到结果不能覆盖新版本或其他对象；局部成功继续可见；失败只重试需要的阶段 |
| 归属、采用、编辑、保存与重开 | 继续使用既有确认、版本和幂等规则；正式成功以真实保存回执与记录ID为准 |
