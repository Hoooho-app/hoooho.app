## 任务与普通案例

家长上传一张收费单，原件与识别任务已受理；识别期间服务切换导致请求中断。再次打开同一对话，应看见原图及真实暂停状态，点击继续后在原任务、原输入和原资源上恢复，获得可核对的首轮资料内容，再显式整理和保存；不能把暂停当成持续识别，也不能重新上传或自动重复付费调用。

## 状态合同

| 状态/分支 | 用户可见与后续动作 | 保留与副作用边界 |
| --- | --- | --- |
| 已接受且运行中 | 消息继续显示处理中 | 保留原件/同一任务，现有真实进度查询 |
| 已接受且paused（含刷新/服务重启） | 停止假转圈，显示暂停和继续处理入口 | 显式resume原任务；不重发输入、不重复上传、不自动调用模型 |
| 任务级failed、无单项失败 | 停止假转圈，显示真实错误和重试这一步 | retry同一任务并复用已完成检查点 |
| 单项failed/needs_review | 沿用现有附件/转写/回应重试入口 | 局部成功保持可见；只重试需要阶段 |
| 本地新输入仍上传/排队，旧任务已停止 | 该新输入继续显示接收状态 | 仅依据包含该输入ID的权威回执停止转圈，不能误判尚未接收的新输入 |
| 继续命令失败/回执丢失 | 原状态与原件保留，入口可以再试 | 命令期间锁定重复点击；不创建新任务 |
| 取消或切换对象/事项 | 取消不复活，迟到回复不得覆盖新工作 | 沿用现有版本、归属与epoch保护 |
| 首轮已完成、后续整理失败 | 已读内容继续可见，提供后续整理重试 | 不重新读图；未保存仍不是正式记录 |

## 核验及交付边界

使用真实持久任务及浏览器，模拟供应商阻塞/失败、暂停、刷新、显式继续和后续首轮内容；断言同一job/input/asset、原图存在、无自动调用、无重复上传、无假转圈及无自动保存。结合现有服务重启/租约持久测试，并保留普通上传/回执/取消及语音重试回归。Production只读核对版本、健康状态和不含资料正文的状态诊断；真实供应商预算210/210不增加，不写Production健康测试数据，不把模拟返回当作真实手机语义验收。
