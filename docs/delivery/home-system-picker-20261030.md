# 首页相机直接使用系统选择界面

基线`493870a79e2409c3dd0d545d50093f7228fca2b8`，干净主线分支`codex/home-system-picker-20261030`。

## 原因与契约

主人要求相机打开后使用系统自带界面，不要应用拼出的来源菜单。核对源码发现：首页虽然没有网页附件面板，但容器存在`hooohoNativeAttachments`时会调用`NativeAttachments.present`；它用UIKit UIAlertController自己拼了“照片图库/拍照/拍视频/选择文件”。使用原生控件不等于系统默认文件选择菜单，此前验证仅覆盖桥接调用，没有区分这两件事。

本轮仅改首页：在点击事件内直接触发已有file input，由WebKit/浏览器决定原生来源菜单及样式，即使原生桥接存在也不调用。`directPhoto`对首页始终开启，不走网页自绘面板。不改Swift、其他页面专用选择器、识别服务、上传限制、相机图标或现有内容。

家长输入一段尚未发送的情况 → 点相机 → 系统选择；取消时不新增消息、不报错、保留文字，再点仍可打开。选图后沿用原有上传/识别/原件保存。选择开始时保留当前requestId，选择返回时同时检查mounted、账户、孩子与requestId，新建/切换后的迟到文件不写到新对话；空文件列表等同取消。文件格式与大小限制、原件/草稿/正式记录边界不变。

系统决定具体选项、语言和呈现，不承诺各iOS版本完全相同，也不再强制四个自定义来源按钮。网页即可切换到此路径，不为本次改动重新打原生包。
