# 孩子档案：分类目录与统一上传

基线：`Hoooho-app/hoooho.app` 的 `origin/main`，`c28bfc054cce8013e842c8989551aaa163789b1a`；干净隔离分支 `codex/child-archive-layout-20261029`。保留其他工作区及未合入的任务。

## 任务与验收

家长为当前孩子查看、补充档案：在顶部确认或切换孩子，从分组目录进入资料；也可在右上角上传报告，沿用现有核对与保存流程，保存后从相应分类重新查看。

- 全站删除自建的“添加到主屏”入口、引导、安装提示监听及其样式和教程资源。已有浏览器应用配置、缓存和 iOS 容器兼容性保留。
- 孩子档案顶栏左侧展示孩子头像、脱敏姓名及性别/年龄，可打开现有对象切换。右上角为唯一全局“上传资料”入口。
- 顶栏不显示重复的页面名称；底导保留“孩子档案”。保留无障碍页面标题。
- 正文全部为档案目录：基本资料（身份与出生背景、生长记录）、健康史（过敏史、慢性病史、家族史、手术史）、儿童保健（儿保与筛查、疫苗接种记录）。这是本次对现有八项入口的分组，不声称完整复刻历史交互稿。
- 每项直接进入已有页面；保留未记录提示、条数、更新标记和原有数据归属。分组采用同一平面列表与分隔线，使用 V2 组件和 tokens。
- 上传沿用 `ProfileUploadBatch`；不调整 API、识别模型、保存规则和下游业务。弹层保持在顶栏外，避免顶栏的背景滤镜裁切全屏上传界面。
- 在 320 / 375 / 390 / 430 和桌面宽度检查顶栏、目录、底导、切换与返回；测试取消选择、上传核对/保存和分类回读；不写真实健康数据、不调用真实模型。

语音中的“华东同／华东天气”暂按现有孩子信息摘要理解，已向用户说明；当前代码无天气模块，不新增天气功能。

## 普通案例与分支

| 阶段/分支 | 归属、状态、结果与后续 |
| --- | --- |
| 进入 | 顶栏取当前孩子，按当前 memberId 请求计数。无成员时目录与上传禁用，可从顶栏选择/添加孩子。 |
| 查看与返回 | 点“生长记录”进入原 `/health-profile/basic`；其他七项使用原路由。编辑和保存由原页面负责，返回后通过原有失效通知刷新计数与更新标记。 |
| 上传普通案例 | 点右上角选一张合成接种回执，核对资料归属、识别结果与归档分类；只有原保存接口成功回执后显示“资料已整理到档案”，刷新目录条数，可进入接种记录回读。 |
| 取消选取/关闭 | 取消系统选择器不建立资料；已添加的本批原件、取消及重试规则保持现有实现。关闭弹层沿用原有丢弃流程，不新增自动保存。 |
| 切换孩子/迟到请求 | 使用原切换接口和本批 pickerOwner 锁定；切换时取消旧计数请求并清空旧计数，不显示前一孩子结果。资料弹层不随顶栏变化重建，不改变已选资料的归属。 |
| 上传失败/重复操作 | 原批量组件保留原件并允许重试；原锁与保存版本继续生效。移动入口不新增请求、供应商调用或保存副作用。 |
| 重开/下游 | 正式档案使用现有持久化及详情/导出来源；本次不修改数据。原上传组件的刷新恢复边界不扩展。 |
