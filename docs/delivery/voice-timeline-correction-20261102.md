# 录音预览回到最新对话气泡

基线 `origin/main` / `7a02ce2`，分支 `fix/voice-in-conversation-20261102`，初始工作区干净。主人实际 iPhone 截图确认上一版悬浮预览不符合要求：文字应进入对话最新位置的专属用户气泡，底部半透明绿色、声波、时长及取消提示下移，透出输入过程；不增加视频能力。

普通案例：在当前孩子已有对话中按住录音 → 在对话末尾立即出现同款白色用户气泡 → 实时快照直接更新同一气泡 → 松手生成原有一条待处理语音消息，已有识别文字继续可见，最终转写按原协议替换；后续追问、保存与重开沿用现有记录。未收到实际文字时只显示输入点，不显示“正在听你说”“正在录音”或额外悬浮框。实时不可用时仅在本气泡说明松开后转写。

边界：只改首页录音呈现及其直接共享组件参数；初始化及其他语音页面保持原模式。未提交预览只在渲染层，不写入草稿／服务器。首次空白首页在录音期间临时收起欢迎区，让最新气泡可见；取消恢复欢迎区，不视为已发送消息，不新增侧栏历史或记录。开始录音主动定位最新处，随后长文字与视口变化跟随末句；用户主动滚动阅读时尊重阅读位置。

取消／恢复：上滑时底部提示取消，当前原话仍在本气泡可见；移回可继续同段录音，松开取消或键盘 Esc 后移除预览且不提交。录音失败、过短、权限拒绝不遗留空气泡；下一段通过现有 hook 清空。松手至原件回调完成按 hook 既有状态切换，不能重复气泡、重复上传或重复业务保存。迟到识别继续受原 hook 的 generation/stopRequested 约束。

责任映射：`SmartRecordWorkspace` 渲染临时 NurseMessage、欢迎区临时状态与跟随；`DialogueComposer/HoldToTalkButton` 仅透传首页模式、禁用浮层预览；CSS 降低绿色区域并把控件整体移近安全区。原件、实时 ASR、提交及保存协议不修改。

验收：已有多条对话末尾、空首页、实时修订、半透明层不遮文字、320/375/390/430 宽度及矮屏、长文字、上滑/移回/取消、下一段清空、松手单消息和无实时文字降级。使用本地真实浏览器及合成音频/识别，不冒称实体 iPhone 或真实供应商验收。检查与发布证据待补录。

本地结果：完整 `npm run build` 通过；Chromium headless shell 实际操作覆盖实时气泡在对话 DOM 最末尾并持续更新同一节点、无浮层预览、320×568/375×667/390×844/430×932 文字与下移控制区不重叠、长文案跟随末句、取消不提交及下一段清空、空首页取消恢复欢迎区、已有实时文字松手后连续显示至最终转写且仅一条消息。无实时文字松手 loading／切页回读与失败重试同任务两项回归也通过。录音时仅将原输入栏绘制透明，保留原指针捕获和松手机制，避免计时与底层按钮文字重叠；取消后恢复。
