# 前台关键信息与只读记录单

基线：`2426aa61f5a8b35b78704dd84e0b3e028e24f432`，干净 `origin/main`；分支 `codex/frontdesk-key-information-20261029`。

## 已确认的任务

家长为顶部选中的孩子自然讲述一件情况，直接补充关键数值/部位/程度，确认整理后看到真实保存的只读记录单；需要时展开细节、编辑、保存修改和重开。

范围：首页纸色、视频缩小、欢迎文案、移除顶部标题、孩子圆角底色、气泡无头像、行尾慢速 loading、底导安全区；按信息类型选择工具，减少无实际信息的中转选项；记录单概述和关键词默认展开，其余默认折叠；确认整理和保存修改取得同一记录的持久回执。保留其他页面、姓名遮蔽、原件、上传核对、身份及事实来源边界、单 Production 政策。此任务明确授权相应追问策略和记录呈现依赖变更，不全局重设计。

## 普通案例与状态

1. 打开首页：纸底延伸至安全区，孩子信息独立圆角浅绿底，欢迎语为“我是记录员‘护护’。有任何情况直接说，我可以帮你整理清楚。”（界面使用中文双引号）。
2. 说“有点发热”：原话接收与理解分开；出现体温输入工具，无预填事实，不先询问有没有量。可拖动或手输后确认，也可直接继续说。
3. 补充“精神和平时一样”：只记精神表现，不把其视为已获得体温，不将未知写成正常。已获得/待补充/待核对对应实际信息；用户明确未知时不重复追问。
4. 确认整理：立即显示进行中；一次事务生成并保存该版本。概述与来源支持的关键词展开，发生与变化、具体表现与测量、精神与生活表现、处理及反应、原始资料折叠。没有资料的段落不伪造正常值。
5. 保存成功才显示“已保存”，不再要求二次“保存记录”。点击编辑才展示输入框，保存修改更新原 ID。重开、日历详情和导出保留同一正文，折叠不删除信息。

## 不变量与恢复

- 当前事项、人物、证据版本及编辑版本仍由现有 context 持有。旧模型结果不得覆盖新输入/人工改动。关键词仅来自当前有效正文，不从被撤回、否定或担心推断阳性。
- 稀疏信息允许保存；不强制填满。起病时间与首次描述时间区分；原有首次描述时间用于排序而非声称用户说了发生时间。
- 新客户端传 `save:true` 将确认整理/完成修改与保存放入既有账户事务；旧客户端省略该字段时保持原协议。重复提交、回执丢失重试仍为同一 ID。失败回滚生成标记和记录，不出现假成功。
- 图片待核对仍保留预览，不自动采用未确认识别内容；保存的是已确认正文/原话与附件，状态明确区分待核对。身份冲突继续阻止串写。
- 合并最新版主分支的“先展示资料初读、再经同意整理”流程：若记录对象尚未核对，确认整理先生成只读结果，显示“待核对记录对象，核对后保存”，不产生正式记录或虚假保存回执。保存意图绑定同一证据和编辑版本；明确核对对象后在同一事务完成保存，失败可重试。新增证据使旧意图失效，须重新确认整理。明确的他人/多人内容仍拒绝串写。
- 连续补充、更正沿用当前事项；切换对象/新对话/返回刷新保留现有隔离及草稿恢复。工具输入不因拖动逐次发请求，只在明确确认时发送。
- 取消编辑恢复已保存正文；关闭/刷新沿用持久编辑草稿；保存失败保留编辑内容重试。外部修改冲突仍拒绝覆盖。
