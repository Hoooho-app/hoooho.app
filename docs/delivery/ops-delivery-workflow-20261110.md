# 总控台：开发与交付工作流

管理员从「工作流 → 开发与交付」选项目。首次接入时，点「App Store Connect API」，核对权限与密钥来源，再沿「GitHub · Apple API Secrets」进入正确仓库的配置位置。看完节点不会改变进度。只有在原平台核对后，才登记该节点的结果；断点、核对时间和历史都留在该项目。开始新一轮 iOS 发布后，复用项目的长期配置核对记录，构建、上传、分发和真机验收使用新一轮独立记录。

| 规则 | 执行与验证 |
| --- | --- |
| 操作指南、口述进度、管理员核对分开 | 只读目录解释入口、前置条件、完成标准和失败排查；用户当时说明正在做的操作不冒称平台证实。手动核对始终标明来源与时间。 |
| 项目隔离，配置与交付轮次隔离 | 项目有独立版本、长期配置记录及各轮历史。新轮不会继承旧构建或安装状态；URL 可直达项目、轮次和节点。原国内、海外、生产发布图保留。 |
| 区分 iOS 交付结果 | 本地检查、CI、签名、上传、Apple 处理、分组可装、iPhone 实际安装及独立商店审核分别记录。需要标记完成时，要勾选对应的原平台核对，适用节点还需填写受限格式的提交、运行或版本/构建编号。旧状态可修正，历史不消失。 |
| 失败与恢复 | 阻塞登记有固定的可用原因、排查入口与下一环。重复提交同一请求只记录一次；版本冲突不覆盖更新后的记录，重读再确认。关闭、刷新后回到已保存状态。 |
| 保密与授权 | 仅现有管理员可读写独立运营台账。表单没有密钥、证书上传、日志或自由备注；只接收状态、原因、规定的回执字段。私有项目目录由部署端注入，勿提交私有仓库元数据或用户操作记录至公开代码。不会调用 Apple/GitHub API、修改权限、自动触发构建或发布。 |

验证使用隔离管理员与项目，不创建生产健康数据、不写外部平台。实际 App Store Connect 和 TestFlight 状态仍以各自平台及设备回执为准。
