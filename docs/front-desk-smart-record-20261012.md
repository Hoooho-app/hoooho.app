# 首页智能记录修复与验收

入口沿用 `NurseStation/HomeFlows.tsx` 的“和护士说说”，路由沿用 `/smart-record?source=front-desk`，仅该首页入口页面化。症状、帮助、反馈维持原入口。

| 需求 | 实现 | 验证 |
|---|---|---|
| 页面、返回、安全区、键盘 | 复用现有 `SmartCaseRecordPage`、`WebPageHeader`、`useVisibleViewport` | front-desk 导航、320/375/390/430、缩短可视高度 |
| 取消恢复选择、每次清爽开场 | 首页直接恢复数据，隐藏已完成历史；两段开场放同一头像组，仅第一段朗读 | 页面恢复、头像与气泡数量、共享对话朗读替身 |
| 历史可靠保存、最新草稿、成员账号隔离 | `FrontDeskRecord` 使用现有 JsonStore/事务；最新按更新时间；相关历史最多8个上下文、每个最多6段文本，不带历史媒体到模型 | 后端上下文隔离、更新时间、幂等重试；本机旧草稿迁移；账号数据集合与成员删除回归 |
| 新话题、相关历史、已保存记录 | 千问在已授权的当前成员候选上下文中选择；已保存事实只读，新补充单独成组 | 后端新意图区分、保存后不重复组织；按需恢复缩略图 |
| 独立文字、录音、图片气泡 | 稳定消息ID、文件字节身份、每次选择一条消息；同消息失败重试；输入时间排序、回复关联 | 中文组合输入、连续两次录音、两次图片、刷新恢复 |
| 文字无法发送 | 原 `sendText` 无提示地因 `pendingVoice` 拦截；首页文字不再被旧录音阻塞，保留中文组合状态保护 | 中文发送、失败原气泡重试；共享入口回归 |
| 图片不显示、不针对图片回应 | 原实现把所有文件集中显示文件名，首页发送不调用对话；改为原图缩略图和真正 `input_image` 千问请求 | 图像字节解码与视觉请求单元测试；连续图片浏览器测试；真实API另记 |
| 图片选择一层、实际转换 | 首页 `directPhoto` 使用无capture系统选择器；HEIC复用真实解码转JPEG，服务器保留原图来源；多图生成真实联系图适配现有单图请求配置 | 系统picker调用/取消、无应用menu、图片失败保留；实体iPhone待验收 |
| 语音原件格式 | 保留主分支已有 codec 参数校验修复、字节快照、decode时复制buffer、16000Hz PCM WAV转换；整理只用转写文字，原件另存 | 新Chromium录音、真实AAC恢复、登录401恢复、整理无二次ASR；原件合同测试 |
| 整理与保存 | 复用现有 ai-drafts 预览/编辑/确认保存；关联确切聊天上下文；保存幂等不变 | 混合来源核对、人工字段编辑刷新、正式保存 |
| 气泡按钮、底部等高、单输入容器 | 使用已有按钮与tokens，首页气泡操作有边框；两侧44px；输入容器集中焦点反馈 | 等高边界、无溢出、气泡操作定位 |
| 麦克风与播放 | 保留串行系统请求、短按取消、页面离开停止并保存已收音内容；停止旧页面播放 | Chromium真实MediaRecorder+假设备；实体iPhone权限、声音待单独验收 |
| 共享入口 | 新能力仅首页启用；共享composer文字处理中规则为显式可选参数 | 帮助、反馈、症状入口回归 |

本机只保留当前草稿、未确认提交的文字/字节及恢复检查点。已提交聊天与原件由后端保存；正式健康记录仍需核对并确认，聊天成功不冒充正式保存。旧草稿上传失败时保留本机原件，不声称已可靠记住。

自动化目前：Client 631 PASS；Server 218 PASS；相关AI/原件/护士/共享合同118 PASS；上下文/账号/成员12 PASS；完整dialogue浏览器17 PASS（含开发模式、图片故障恢复、旧录音不阻塞文字、录音期间暂停回复朗读）；typecheck、production build、diff check PASS。测试替身套件在独立fixture进程中使用更高的总调用预算，生产限流、密钥与模型配置均未改动。

自动化麦克风、模型、朗读替身只证明各自流程。真实千问调用、部署SHA和生产功能验收记录在发布验收产物中；实体iPhone未验收前不记为通过。

真实Staging首轮调用：文字对话成功；图片请求到达千问并返回HTTP 200，但在schema_validation根类型校验失败，错误码AI_OUTPUT_INVALID。首页回复改用专用格式；仅解包一个严格有效的回复对象数组，其他入口与非法响应仍拒绝。补充23项供应商/上下文合同检查与解析评估2项，均通过。录音停止到字节落盘期间，返回不等AI；快速再次进入同成员仅等待原件最终保存，避免旧组件迟到写入覆盖新草稿。

真实图片与ASR均已通过。随后复现INVALID_JOURNAL_SYMPTOM：抽取的饮食/睡眠字段与症状类别元数据不一致，时长被放入sleepAt。新增可选frontDeskRecord，仅首页启用既有字段合同的元数据纠正；值、逐字引文、原件均不改写，时长不计算成时刻或分钟。其他入口继续严格按原合同。人工类别/字段修改保持优先。补充恢复后MIME声明变化的字节签名回归，验证同录音重试不重复且伪造WAV仍拒绝。
真实历史图片召回复现了保存来源与可见媒体共用列表的问题。已保存原件改为单独恢复到气泡显示表，不加入新记录材料；历史检索补充附件描述与原护士观察。新增已保存图片可见且不出现再次整理按钮的浏览器断言。
