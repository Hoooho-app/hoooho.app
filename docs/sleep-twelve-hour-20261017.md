# 睡眠页 12 小时表盘与日期标注

基线：`Hoooho-app/hoooho.app` 的 `origin/main`，`9307d089bafe4e3eeae4494a4dda5fb469478854`。工作分支：`codex/sleep-twelve-hour-relative-dates-20261017`，开始时工作区干净。

## 验收范围

- 手动记录睡眠页为标准 12 小时表盘：12 在上、3 在右、6 在下、9 在左，完整显示 1–12；拖动一圈精确增加或减少 12 小时，跨日日期与真实时长保留。
- 表盘上方不出现“下午 PM”或 AM/PM 提示。入睡、醒来的时间上方分别显示相对当前日期的“今天／昨天／前天”；更早的日期显示完整日期。按记录时区计算，不能用入睡日代替今天。
- 具体时间使用 12 小时数字，并在时间旁保留小号 AM/PM，避免同一天上午和下午无法区分；日期编辑和保存仍使用现有真实时刻。
- “睡得怎么样”统一常规字体、白底、标准浅边框、标准高度与右箭头。现有选项、摘要与保存失败重试保持可用。
- 冻结其余页面、自动记录模板、接口、持久化结构和原有业务数据。共享自动睡眠编辑器的已有状态流程不改变。

## 验证与交付

相关时间单元测试、睡眠页手机宽度浏览器操作、构建；核对最终差异后提交、推送并集成 main，依次验证 Railway Staging 与 Production。浏览器模拟不等于实体 iPhone/Safari 验收；技术验证不代替产品负责人视觉验收。

本地结果：完整构建通过；`TZ=Asia/Shanghai npm run test:client` 664/664；手动睡眠页浏览器测试 3/3（375／390／430 宽度，含真实拖动一圈增加 12 小时、昨天/今天/前天、日期编辑、失败重试与落库）；共享编辑器浏览器测试 4/4（含自动实例）。截图检查无横向溢出、时间和角标重叠。全量客户端测试最初在宿主 UTC 下有既有本地日历用例失败，按应用上海时区重跑全部通过；未修改无关日历逻辑。旧共享编辑器测试的 Windows 浏览器路径仅在忽略的本地配置中覆盖。
