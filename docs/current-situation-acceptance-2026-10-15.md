## 允许范围

仅「目前情况」区域及该区域的测试；另按用户要求统一 `AGENTS.md` 中的长期执行规则，纠正 V1/V2 权威文档冲突。
不改变其他页面、后端、API、数据结构、AI 提示词与处理逻辑。

## 验收条目

- 「更改主诉」前置，为绿底白字主按钮；无主诉时提供「选择主诉」。
- 模块标题为绿色，正文、标题与按钮沿同一左边界。
- 情况描述、症状表现、近期饮食分别就近编辑；编辑按钮为低矮灰底，保留可触摸范围。
- 「本次重点」跟在「情况描述」标题后；「查看原话」独立放在描述下，不混入描述正文。
- 附件独立成块，紧接近期饮食（没有饮食时接在前一个可用模块后）；提供「继续添加」。
- 「发生与变化」「已做处理」如有数据继续展示，不删减内容。
- 症状表现中的「体温曲线」只在核验到至少两条测量时出现，不加右箭头。
- 体温曲线从底部弹出，不增加当前成员、记录条数等说明；关闭及返回后回到原位置。
- 编辑取消、失败重试、保存再刷新、附件管理、无主诉/无饮食、较大字体、曲线资格变化继续可用。
- 375/390/430px 浏览器模拟没有横向溢出；模拟结果与实体 iPhone Safari 验收分别报告。

## 相同执行路径

构建：`npm run build`。
服务回归：`npm run test:visit-sheets`。
浏览器回归：`playwright test --config tests/visit-sheet/current-situation-v2.config.ts`。
跨环境浏览器路径通过 `VISIT_E2E_CHROMIUM_PATH` 配置，不依赖某一台 Windows 的浏览器位置。
发布验证：`node tests/visit-sheet/current-situation-release.mjs https://staging.hoooho.com`，然后在正式环境运行同一脚本。预发布自定义域名不可用时，使用同一服务的 `https://hooohoapp-staging.up.railway.app` 原生域名。
该发布脚本只创建并清理自己的合成成员，不调用付费模型，不使用真实孩子资料。
本任务的视觉差异仅为附件模块顺序及「继续添加」文案；其余已存在的确认条目进行回归验证。
