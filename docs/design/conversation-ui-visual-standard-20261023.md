# Hoooho 全局 UI 视觉执行规范：对话范式

版本：对话范式 1.0 草案；日期：2026-10-23。供 Codex 实施与验收使用。信息架构沿用已认可的 V3；本稿规定渲染方式，用户于本轮明确授权实现整套方案并直接部署正式环境；不改写无关业务。

## 一、基线与适用范围

Hoooho 的目标感受是安静、可信、亲近、清楚。高级感来自稳定的文字层级、对齐、留白与材质一致性。默认沿用现有 Design System V2 组件及 `--hoho-*` 命名，不建立第二套按钮、输入框或主题。

2026-10-23 已读取 GitHub 默认分支：`src/styles/tokens.css`，SHA `93497d5bf5a9e877655a8c4bac56d90456a36e55`；`docs/hoooho-design-system-v2.md`，SHA `2cc824bb08910eea7694ea0abcaf0148fc2f7bc5`。文档 Foundations 的品牌绿、圆角与当前代码不同。实施以核验时的 `tokens.css` 为运行值，先在文档中记录差异；不得用旧说明全局覆盖现有主题。落地前重新核对 `origin/main`，避免覆盖后续变化。

全局渲染原则适用于护护客户端的对话、档案、记录卡、表单、列表、抽屉、底部弹层和导出预览；页面级保护边界仍然有效。家庭统筹网页、后台及已冻结业务页面不因本稿自动迁移。首轮实施顺序为对话首页、共享组件必要扩展，再逐页审阅和应用；新接待区是本轮待验收的 opt-in 提案，不自动引发全站 CSS 迁移。

## 二、已经确认的结构

- 首页是护护的对话空间；保留现有护士台视频及 Logo，不重新生成人物或改画桌台。
- 侧边栏保留服务前台、健康日历、孩子档案、一键整理；保留呵护之旅、辅助工具、产品中心及账户。辅助工具的忌口卡、排敏观察、配料表扫描、用药安排、照顾交接单继续存在，产品中心继续含设置、帮助、反馈、关于。对话记录独立收纳为一项。
- 输入框上方的五个标签按原顺序：记录症状、喂养/饮食、日常、用药、就诊资料；日常展开睡眠与排便。文字、顺序和去向均不改。
- 顶栏保留侧边栏、护护、搜索与更多。更多只有新建对话、分享护护、产品介绍；不恢复“查看全部功能”。不新增底部导航、医生智能体列表、播报开关或未开放的任务入口。

## 三、颜色与表面角色

| 角色 | 当前 token | 当前参考值 | 使用位置 |
|---|---|---|---|
| 操作主色 | `--hoho-color-action` → primary | `#486253` | 主按钮、发送、明确选中态 |
| 操作浅底 | `--hoho-color-primary-soft` | `#EBEFE6` | 选中项、轻提示；不铺满普通页面 |
| 页面 | `--hoho-color-page-background` | `#F4F2ED` | 内容外部的稳定纸色底 |
| 普通表面 | `--hoho-color-surface` | `#FCFBF7` | 普通列表与设置区域 |
| 对话白底 | `--hoho-color-surface-white` | `#FFFFFF` | 接待区、对话核对卡等既有白色变体 |
| 分隔线 | `--hoho-color-border` | `#D6DAD3` | 1px 分隔、输入边界 |
| 正文 / 次级文字 | text-primary / text-secondary | `#273332` / `#5E6961` | 标题正文 / 时间来源说明 |
| 品牌资产 | 使用原 Logo 文件 | 资产原色 | Logo 保留原 Hoooho 绿 `#1B7A6E`，不据此改写操作主题 |

以上是核验时的默认主题值，会员及已有主题继续读取其 token 覆盖值，不在组件内硬编码并使主题失效。成功、警告、错误、信息继续用现有语义 token，并配文字或图标。既有记录类别颜色仍用于日历、资料类型等原定范围；输入框上方五个标签属于中性操作，不各自铺一种类别色。正文不使用透明度来减弱，应使用可读的次级颜色。普通文字与实际底色对比至少 4.5:1；大字及有辨识作用的图标、状态和焦点指示至少 3:1。装饰性分隔细线可以保留低对比度，不宣称所有 #D6DAD3 细边框已达到 3:1。

## 四、护士台与文案的一体化接待区

这是本轮优先验收项。视频自身是白色场景，接待区与视频必须共享同一层纯白表面。把视频和问候文案放在同一个容器内；视频外不再套独立白色方块、边框、阴影或光晕。外容器可与纸色页面保持区别，场景与文案之间必须没有可见的色块断口。

参考手机宽度 390px：页面左右边距 16px，接待区外宽 358px；内边距 16px；视频占 112px 的方形位置，保持 1:1 与完整桌台；文案区可伸缩，图文间距 8px。问候主文案 22px / 1.45，“Hi”和说明均 13px。问候和两行主文案形成一个视觉组，次级说明置于其下。320px 宽度时：同一接待区外宽 288px、内宽 256px；视频 88px、间隔 8px、文案区 160px，问候降为 20px 以保持两行。更大无障碍文字或更窄可用空间时，允许同容器内上下排列，不挤压、拉伸或裁掉护士与 Logo。静态手机外壳不计入产品边距，不能用占布局的 1px 外框削减参考宽度。

接待区圆角 24px 是拟新增的组件专用 opt-in token（建议 `--hoho-radius-reception`），只服务本轮接待组件；它不覆盖既有 `--hoho-radius-card`，也不是全站卡片圆角的新默认值。

资产直接使用现有 `nurse-station-idle-1.mp4` 和对应 poster。保持 `muted`、`playsInline`、循环；后台、不可见或减少动态时暂停。视频未就绪、受限或失败时显示同尺寸海报，不塌陷、不跳位、不弹错误遮住问候。禁止 `mix-blend-mode`、强曝光、透明渐隐遮罩、抠像或滤镜来伪造融合；融合由共同白底与统一布局完成。预览所需的兼容格式可以转码，角色、构图、时长和动作内容保持一致。

## 五、文字、间距与布局

使用现有平台中文字体栈，不为“高级感”引入在线字体。常规页面、区段和卡片标题 600，标签 500，正文 400；仅接待区的友好开场标题使用 500。对话界面采用 `--hoho-font-family`，若问候需无衬线应作为组件角色，不全局改写现有标题字体 token。

| 层级 | 尺寸 / 行高 | 规则 |
|---|---|---|
| 对话开场主文案 | 页面标题字号 token，22px / 1.45 | 接待组件专用行高，通常两行 |
| 页面 / 区段 / 卡片标题 | 22 / 18 / 16px | 对应既有标题角色 |
| 正文 / 对话次级正文 | 15px / 1.6；14px / 1.6 | 长文清晰，不压缩字间距 |
| 标签、时间、来源 | 13px / 1.5 | 普通说明保持 13px |
| 短状态徽标 | 12px / 1.4，500 | 仅短状态，不外推到普通说明 |
| 编辑输入 | 至少 16px | 避免 iPhone 自动放大；placeholder 不代替标签 |

间距使用 4/8/12/16/20/24/28/32/40px。页面边距依现有 gutter；组件内常用 12/16px，区段之间 20/24px。同一页面保持统一左对齐线，标题、字段和动作不要各自漂移。数值、时间与单位用等宽数字，文本仍用比例字形。五个底部标签均至少 44px 高，正常字号 13px；320px 窄屏必要时允许这五项降至 12px，属于局部例外，不能外推到正文、字段和全局标签。

圆角以当前代码为准：small 6px、control 10px、card 14px、overlay 26px；输入框 26px 是本轮对话组件的局部变体，不修改全局控件圆角。胶囊只用于真实状态、分段选择与圆形操作。普通列表用连续平面与分隔线。接待区可无投影或继承现有 `--hoho-shadow-card`，不得另造专用投影。阴影只调用现有 card/floating/overlay，不手写更浓的投影；同屏避免多个抢眼浮层。图标用现有 Lucide 与自有图标，通常 20px，线宽约 1.7–1.8；触控热区仍至少 44px。

## 六、共享组件与状态

优先复用 `HohoButton`、`HohoInput`、`DialogueComposer`、`HoldToTalkButton`、`HealthCard`、`HohoSurfaceRow`、`HealthTag`、`StatusNotice`、`BottomSheetSurface`。缺少变体时先扩展共享组件，并记录适用角色；不得在页面内复制一套相似组件。

输入区沿用本轮认可的视觉组织：语音、文字、相机与添加入口；有文字时提供发送；五个中性操作标签位于输入区上方，不删除、改名、重排，也不额外增加主按钮。正式代码需收敛进 `DialogueComposer` 的明确变体。录音、识别、整理与保存的进度和恢复动作出现在会话内，不叠加第二排状态工具栏。弹层只有一个明确关闭入口，支持 Escape、焦点限制、返回焦点和安全区。

记录卡先突出“发生了什么”，再给时间、处理与来源；未确认与已保存必须用明确文字区分。用户气泡和 AI 文字保持稳定间距。抽屉、搜索、弹层、列表同时规定默认、按下、焦点、加载、空、失败、禁用与成功状态，不能只交付理想数据画面。

## 七、动效与真实状态

反馈 140ms、普通切换 200ms、复杂展开 280ms，使用已有 easing。移动幅度小，动效解释出现、展开和去向；不用循环装饰、弹跳或长时间模糊。减少动态时移除装饰性转场并暂停视频，状态反馈仍可读。

首页问候属于会话开场，发消息后随连续内容上移；上翻可以找回。用户上翻时不强制滚底。键盘上沿承接输入区，安全区与四行长输入均不遮住当前内容。查档案再回来时保留当前孩子、草稿、原会话与阅读位置。

视觉反馈必须对应真实阶段：接收不等于整理完成，生成草稿不等于保存，预览不等于分享。保留用户原话；家长怀疑不能写成确诊或过敏史；未提供不写成正常。示例数据标为示例，空状态不编造记录、任务、统计或提醒。

## 八、交付与验收

Codex 先列出当前基线提交、授权页面、保留功能和拟改的共享组件，再做最小变更。本轮已授权的直接依赖仅包括新增按账号与孩子隔离的只读对话历史列表接口、历史入口及三项更多菜单；归档只读，不引入跨会话重放或新的保存语义。除此之外，此规范不授权改 API、AI 解析、存储、数据模型、文案含义、导航结构或业务流程；不替换视频、Logo、原表单和旧数据。原型样式不得整段复制进生产。

视觉验收应至少覆盖 320、375、390、430px 和现有 620px 最大手机壳宽度：无横向溢出，五个标签可读且可点，接待区图文同色且无独立白块，完整侧栏与三项更多菜单正确。另检查长姓名、长段落、多图、空数据、失败重试、大字号、键盘、减少动态、视频 poster 回退，以及切换后草稿不丢。自动截图、对比度或构建结果是辅助证据，最终视觉接受由产品负责人确认；浏览器模拟与真机 iPhone 验收分开记录。
