# 前台视频去白底

任务：家长打开症状记录页时，原护士站人物直接在当前页面背景上播放，不出现与紫色／纸底冲突的白色方框。本次只调整首页欢迎视频，不改背景主题、人物、文案、尺寸、输入、记录和保存流程。

基线 main `3784d7a`；隔离分支 `codex/nurse-video-background-20261029`。用户新要求覆盖本处历史“不裁切”限制，仅去背景，原视频和完整前台主体保留。

普通案例：打开已有孩子的症状记录页 → 先显示透明海报 → 解码后同帧合成透明动画 → 保留原有循环、离屏／后台暂停、减少动态效果及手势后播放恢复。首次添加孩子后也使用同一欢迎组件。切页／卸载取消帧回调并释放视频；回页重建。加载／解码／画布不可用时保留透明静态海报，不重新露出白底，不阻挡记录输入。无业务对象、数据或接口变更。

原 360×360 / 24fps H.264 素材不改写。离线从外缘连接的纯白背景生成逐帧蒙版，保留白衣、帽子与静止白色柜台轮廓；不依赖在线模型。RGB 与灰度蒙版上下打包在同一个视频内，提供普通 VP9/WebM 和 H.264/MP4 两种编码，用轻量画布恢复透明度，避免依赖 iOS 不一致的透明视频解码，也避免两个视频不同步。海报取自同一处理流程。制作脚本 `scripts/prepare-nurse-cutout.py` 只用于开发，依赖 Pillow/numpy/scipy/ffmpeg，不增加客户端或 Production 依赖。

验收：320／390／430px 实际浏览器检查透明边缘、白衣保留、无白色矩形、动画逐帧变化、视频循环、减少动态效果、素材失败和切页恢复；验证构建与既有首页交互。不调用付费 AI，不写 Production 健康数据，不发布原生包。浏览器模拟与实体 iPhone 验收分别报告。

本地验证：`npm run build`、806 项客户端检查、原媒体及透明媒体完整性检查通过。Chromium Headless Shell 在 320／390／430px 共 12 个透明视频场景及 2 个既有首页／键盘草稿场景通过，截图检查纸底和紫色底，保留白衣与柜台。普通 Chromium 在此执行环境受 Unix socket 限制，改用已安装的 Headless Shell 完成真实浏览器模拟；实体 iPhone／Safari 尚未由产品主人验收。发布状态以对应 main 提交、Railway SUCCESS 和线上资源为准。
