# AI nurse recording — nurse-v1

Implementation date: 2026-10-07. The existing symptom form remains the confirmation surface. The first-level navigation, manual form, body locator, media pipeline and segmented ASR are retained.

## Additive interfaces and storage

- `POST /api/members/:memberId/nurse-drafts`: open/resume this account, member and event/task scope. No model request on open.
- `GET/PATCH /api/members/:memberId/nurse-drafts/:id`: owned draft, optimistic version, immutable final turns, full review form, explicit discard.
- `POST .../:id/generate`: Bailian JSON organization or text conversation; semantic voice intent/emergency assessment uses `assessOnly`. No automatic paid retry.
- `POST .../:id/sdp`: server-authenticated Beijing workspace WebRTC SDP. Long API key stays on the server. Browser receives SDP and policy/context, never the key.
- `POST .../:id/usage`: bounded numerical realtime receipts; client receipts are not authoritative billing statements.
- Existing case-record and quick-record APIs save optional `journal.aiNurse` together with the existing symptom record. No second clinical record database, migration or existing-row rewrite.
- `nurse-drafts.json` holds scoped drafts and usage metadata in the existing protected data volume. Account deletion removes them; guest merge transfers ownership. Saved drafts cannot be discarded. Old records without this optional metadata remain valid.

Version `nurse-v1`: final `turns` with IDs, role, order, event time, correction links and interrupted status; optional dynamic `professionalNotes`; user-only `fieldSources`; organization snapshots; existing record revision history for confirmed edits. AI questions cannot be field/note sources. Original turns are immutable after save. Server uses exact user quote fragments for generated narrative and note bodies, because a real model paraphrase incorrectly changed “previously” to “this morning”. No presumed time, dosage or confirmed allergy is accepted from that paraphrase. AI note attribution defaults to parent: no authenticated doctor record is supplied in this conversation. Parent concern remains unconfirmed. Manual editing remains explicit and source turns are retained.

Atomic record creation, saved-draft marker, idempotency request and media association use the existing account transaction. Same request retries return the same record. Existing request-result recovery is retained. Failed media association rolls back event, record, request marker and saved marker together. The list counts one symptom record and shows a lightweight note count. Search, same-record detail/edit, medical preparation, default consultation summary and standalone HTML include qualified notes; raw conversation is an optional source appendix.

## Runtime configuration and realtime behavior

Existing server settings: `AI_PROVIDER=bailian`, `BAILIAN_API_KEY`, `BAILIAN_BASE_URL` (Beijing workspace compatible endpoint), `BAILIAN_MODEL`. Optional `BAILIAN_REALTIME_MODEL` defaults to account-tested `qwen3.8-omni-flash-realtime`. No new secret or change of provider/region. Unsupported runtime/configuration, permission failure or network failure preserves manual/text/segmented-ASR entry.

SDP uses the existing Bailian HTTPS transport's scoped 1000 ms address-family connection window and verified TLS, locked to the exact workspace/model SDP endpoint. The initial Staging application check exposed native Node fetch `ETIMEDOUT`; this transport correction and safe failure classification are covered by regression tests. It does not change global networking, relax TLS, redirect or automatically retry. Realtime context includes only current time/timezone, member birthday/relationship/gender, this conversation and review facts.

Audio starts only after explicit click, connected transport, DataChannel and `session.updated`. Native WebRTC handles final ASR and voice response; final user turns also pass the existing text model for semantic organization consent/emergency checks, without duplicating a normal assistant turn. This extra assessment is metered. No phrase whitelist chooses organization. Pause, hidden page, offline, pagehide, exit and review stop tracks/player/peer/channels/timers. Sessions are bounded to five minutes with explicit resume. Barge-in cancels the response, detaches local playback and retains only displayed partial text as interrupted; late cancelled completion cannot clear a newer response. Autoplay denial stops the microphone and offers an explicit play/resume button. No automatic reconnection, infinite retry, raw recording persistence or offline queue of audio.

Final text awaiting a failed write stays in a bounded, account/member/scope-specific session draft with manual retry. Logout clears visible state; the review cache and unsynchronized final text remain in account/member/scope-isolated session storage for same-account recovery. Unsynchronized final text remains in its isolated session draft for same-account retry, never loaded by another identity. Synced drafts stay in protected server storage for re-login. Review sync includes existing body selections, date precision, manual notes, field edits and deletion markers. Unsent input and unsynchronized offline text cannot be promised recovered after browser/session storage is destroyed; the UI marks unsynchronized text and prevents organization until retry.

## Clinical and privacy verification boundary

Policy: at most one useful question per turn; no diagnosis, prescriptions/dose changes, food rechallenge, allergy-history promotion or guessed emergency number. Current child respiratory distress/cyanosis/unresponsiveness gets immediate local emergency help advice; record completion is never a prerequisite. Model semantic assessment is independently checked for exact latest-user evidence and denial, resolved past, hypothetical/third-person vetoes. A later current danger overrides an earlier normal statement. This is a bounded engineering regression, not clinical validation or proof that all emergencies can be excluded.

### Context, extraction and compatibility

- Owned draft PATCH accepts an additive `formContext` with the current existing symptom form. Empty complaints are allowed only for this draft context; formal saves keep strict journal validation. Dates survive review restoration as dates, rather than being dropped by the metadata whitelist.
- Structured organization supplies short `tN` transport aliases while retaining immutable original turn IDs in storage. Quote candidates are exact original user turns/sentences/clauses. Schema enums prevent invented IDs, ellipsis joins and rewritten quotations. Backend validation still checks the chosen quote against the actual referenced user turn and requires evidence for every nonempty field. Assistant questions cannot supply facts.
- Severity output is allowed only when the parent explicitly says the existing severity labels; absence of a special reaction cannot imply mild severity. The parent’s actual reaction and uncertain change belong in the complaint, independently of treatment response. Normal conversation/assessment does not apply unused extraction proposals, so an irrelevant rejected note cannot block a chat reply.
- Referenced form commands cannot become complaints or onset dates. Unsupported location/time proposals remain empty, preserve the original manual form and return explicit review warnings. Face/cheek references can map to the existing coarse face locator when the child's model is known; no left/right or specific eye/skin point is guessed. Other locations require literal source support and remain manually editable.
- Optional `NurseFields.timeText` preserves quoted fuzzy time. Existing `journal.timeLabel` is now validated/persisted (160 characters maximum), with `timePrecision: unknown`; no occurrence day is inferred from “this week”. List, detail/edit, consultation reading and export retain the words and unknown-date qualification. Old period labels are not mislabeled as unknown dates. No database migration or historical-row rewrite is needed.
- Manual field/date/locator edits are tracked before the first nurse opening. New differing nonempty proposals show a comparison; unselected fields keep the parent's version. An explicit AI time selection switches to unknown precision. Restoring an already reviewed draft does not prompt as if it were a new proposal. Deleted/edited notes retain the established protection.
- Save failure keeps the original form, edited notes and dialogue, shows Retry save, and uses the existing atomic/idempotent save. Only a successful API result shows saved state. Draft review warnings are not added as clinical facts or exported notes.
