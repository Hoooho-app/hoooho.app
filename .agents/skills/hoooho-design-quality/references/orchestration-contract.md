# Orchestration contract

## Review lanes

Each lane receives the same frozen decisions and evidence schema. Return route/state, observable issue, evidence, severity or score impact, root cause, smallest safe remedy, automatic-fix permission, and verification method. Label static suspicions separately from browser-confirmed defects.

The primary agent owns scope decisions, conflict resolution, source edits, commits, and release. Do not mechanically average visual opinions; the visual director selects the coherent direction.

## Batch gates

For each implementation batch record its finding IDs, shared root, changed files, before/after screenshots, interaction checks, console/network status, automated tests, regressions, and accept/revise decision. Do not begin the next propagation batch when the current one fails its direction or interaction gate.

## Stop conditions

Stop only for a frozen product decision, unsafe user-work conflict, important production dependency, irreversible operation, unavailable required credentials/environment, persistent test/build failure, failed staging, or material production risk. Ordinary typography, spacing, hierarchy, component, motion, and responsive choices remain professional design decisions within the authorized presentation boundary.

## Completion threshold

Completion requires validated Skills and governance docs, a recorded first audit, implemented in-scope improvements rather than advice alone, stable before/after evidence, independent visual and interaction review, full applicable tests, clean focused commits, push/main integration, and staging/production verification when runtime output changes.
