# Hoooho 健康时间轴列表高难度多模态专项测试报告

## 结论

总体结果：**PARTIAL**。52 个用例均已登记结果，其中 `PASS 3 / PARTIAL 7 / FAIL 13 / BLOCKED 29`。这个总数只表示用例处置状态，不能当作一个跨模态通过率。

- 转写后文本链路（B01–B16）：`PASS 3 / PARTIAL 4 / FAIL 9`。
- 受控合成音频（A01–A12）：12 个 WAV 素材生成并通过 RIFF 校验；真实 ASR E2E 全部 `BLOCKED`，因为自动化浏览器麦克风权限被拒，且产品基于 Web Speech API，没有把 WAV 注入识别器的测试接口。
- 图片（P01–P18 中的图片用例）：文件选择和附件持久化可运行，但视觉提供商未配置（`VISION_NOT_CONFIGURED`）；完成代表性上传、边界、无关图、重复图、三图顺序和耗时测试，其余识别案 `BLOCKED`。
- 图片+语音（P07/P08/P12、M01–M06）：9 个全部 `BLOCKED`。没有把图片结果与转写文本拼接后冒充多模态 E2E。

未修改业务代码、未使用真实用户数据、未访问智能查看或护士导诊、未部署产品版本。

## 缺陷清单

### P1

1. **否定、变化与次数大量丢失**：B03、B07、B12；B07 甚至把“今朝没吐了”降成未带状态的“呕吐”，可能误导当前状态。
2. **常见短句与口语覆盖不足**：B02、B05、B06、B09、B11、B13、B14、B15 均无法形成有效事实。
3. **图片分析环境不可用**：附件可保存但所有识别降级为“图片记录”，无法验证温度、药盒、化验单、处方、皮肤图或截图语义。
4. **大图/HEIC没有达到测试期望**：8MB/21MB不压缩，HEIC直接拒绝。
5. **重复图片未去重**：P15 同一文件连续选择生成两个附件。

### P2

1. B08 能保留原文和核心温度/呕吐，但丢失次数与“精神差”。
2. B10 正确处理当前值纠正，但未将明确的昨天39.6℃保存为独立历史事实。
3. P13 对无关图不生成结构化健康事实，但仍创建无意义“图片记录”，不满足零入库期望。
4. 性能观测没有分阶段遥测，无法区分预览、压缩、上传、AI与列表刷新。

未发现 P0 数据破坏或越权问题；所有写入均在隔离合成数据目录。

## 关键安全问题回答

- 是否把背景声、电视内容、成人说话或指令当成患者事实？**真实音频链路 BLOCKED，不能作肯定结论；B16 文本指令注入成功拦截。**
- 是否凭图片自动诊断疾病或把药盒当成已服药？**视觉分析未运行，当前只降级为图片记录，没有产生此类虚假事实；但这不是视觉安全能力通过。**
- 是否会把否定句转成阳性事实？**B12 没有生成发热/呕吐阳性，但否定事实也没有被结构化；B07 的“今天未再呕吐”丢失，时间轴只显示呕吐，存在当前状态误导风险。**
- 是否正确处理自我纠正？**B10 的当前38.6℃正确，未把39.6℃当当前值；历史值未单独落库。**
- 无关输入是否零入库？**文本B16是；图片P13不是，仍生成1条“图片记录”。**
- 是否保留来源可追溯性？**文本原文完整保留；图片附件与记录ID可追溯；合成音频未进入ASR，不能验证语音来源。**
- 是否会伪造未观察到的事实、数值、诊断或趋势？**本次已执行文本/图片代表案未见新疾病诊断或虚构数值；主要风险是漏识别和状态/否定丢失。**

## 限制与后续建议

1. 在受控测试环境提供可注入音频文件的 ASR 测试适配器，明确标记 `controlled_audio`，并与真实麦克风 E2E 分开报告。
2. 配置隔离视觉提供商后重跑 P01–P14 与全部 M 组；在此之前不能给出 OCR 准确率或多模态冲突率。
3. 为事实解析优先补充否定、变化、次数、上下文短句、生命体征和用药短句回归集；修复工作应另开任务，本报告没有修改业务代码。
4. 为图片入口增加去重、压缩/HEIC能力以及分阶段性能遥测后重跑 P05、P15、P17、P18。
